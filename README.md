# Лабораторна робота №7: Робота з базами даних у Python

**Тема:** Організація шару зберігання даних (persistence layer) за допомогою реляційної СУБД SQLite, SQLAlchemy ORM, міграцій Alembic та патерну Repository для системи банківських рахунків (Варіант 4).

**Автор:** Войтович Максим Андрійович (група ФеП-31).

## Опис проєкту

Проєкт розширено повноцінним шаром персистентності даних. Замість роботи виключно в пам'яті чи з файлами, тепер використовується реляційна база даних **SQLite**, керована за допомогою сучасного **SQLAlchemy ORM**. Архітектура проєкту побудована на основі **Repository Pattern**, що забезпечує чітке відокремлення бізнес-логіки від деталей збереження даних. Також налаштовано систему міграцій за допомогою **Alembic** та створено комплексний набір інтеграційних тестів із використанням `pytest`.

## Основні можливості та архітектура

- ** SQLAlchemy ORM:** Описано реляційні моделі (`Client`, `Account`, `Transaction`) із використанням сучасного синтаксису `DeclarativeBase` та `Mapped`.
- **Зв'язки між таблицями (Relationships):** Реалізовано зв'язки типу *one-to-many* між клієнтами та їхніми рахунками й транзакціями.
- **Паттерн Repository:** Відокремлено операції доступу до даних (`ClientRepository`, `AccountRepository`) від бізнес-логіки.
- **Транзакційність та ACID:** Реалізовано безпечні перекази коштів (`transfer_money`) з використанням механізмів `commit()` та `rollback()` для гарантування цілісності даних (атомарність).
- **Підтримка DB-API:** Додатково реалізовано прямі параметризовані SQL-запити через стандартний модуль `sqlite3` задля уникнення SQL injections.
- **Міграції бази даних (Alembic):** Налаштовано конфігурацію та створено початкову міграцію для керування структурою БД.
- **Інтеграційне тестування:** Написано надійні інтеграційні тести з використанням ізольованої бази даних у пам'яті (`sqlite:///:memory:`) для перевірки CRUD-операцій, транзакцій та обмежень (заборона від'ємного балансу).
